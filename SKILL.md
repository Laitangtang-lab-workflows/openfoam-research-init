# OpenFOAM Research Init — methodology & toolchain for simulation research projects

Directory organization, data discipline and companion engines for OpenFOAM simulation research (solver development, parameter sweeps, phase-map/mechanism studies): **four-line layering** (code/data/docs/cases separated, one-way data flow), **two-bucket rule** (raw read-only / derived regenerable), **case ledger discipline** (freeze before running), **explicit-parameter philosophy** (zero hardcoding in case generation), **fully auto-generated 00-index**, **three-replica audits**, **AGENTS structure audit**.

> Default directory names in this convention are Chinese (`代码` code, `数据` data, `研究文档` research docs, `算例集合` case archive, `公共库` shared library, `AI记录` AI notes). They are *convention names*, not requirements: every one of them maps to a config key (`works_prefix`, `docs_dir`, `code_dir`, `pub_dir`, `ai_notes_dir`) and can be set to whatever names your project uses.

## Quick reference

| Dimension | Iron rule |
|---|---|
| Four-line layering | `代码\` (pure scripts, zero data) · `数据\` (two buckets) · `研究文档\` (narrative mainline + 00-index) · `算例集合\` (frozen input archive) — one-way data flow `raw →(code)→ derived →(written into)→ research docs`; outputs never feed back into inputs |
| Two-bucket data | `原始\` raw = first-hand sources, **read-only**; `衍生\` derived = code output, **regenerable**. Rule of thumb: cannot be regenerated by a script → raw; can be produced by running code → derived; figures embedded in documents → live with the documents. The in-repo raw bucket stores **text only**; binary raw material (images, video) goes to a synced-drive `数据\原始\` twin; derived files go to the bucket nearest their source, dual-source derived always into the in-repo `数据\衍生\` (details in repo-layout §2.1) |
| Case freeze | **A case must be frozen, locked and registered in the case archive before it enters a compute environment** — freeze before running, never archive afterwards |
| Double ledger | `00-算例台账.md` (case ledger, one row per case: origin / status / runs / where results went); `00-运行台账.md` (run log, one row per run: run id + commit prefix + machine + status), cross-linked by run id |
| Explicit parameters | Case generation = shared library + per-condition driver scripts, **all parameters explicit** at the top of the script; shared library has zero third-party dependencies and no machine paths; intermediate artifacts such as STL are deterministically regenerated, never stored |
| Script addressing | Scripts anchor to the project root via `__file__`, never relying on the caller's working directory |
| Top-level conventions | `手稿\` (manuscripts) `AI分析\` (frozen AI snapshots) `operations\` (pipeline runtime) stay at the top level; the asset library stores only non-regenerable material; final .ai files export tiff+png (500 dpi, artboards off) — see [references/top-level-conventions.md](references/top-level-conventions.md) |

## Engines (scripts\, all project differences via config)

| Engine | Responsibility | Invocation |
|---|---|---|
| `index_generator.py` | Fully automatic `研究文档\00-索引.html` generation (dependency tree / health check / data flow / borrowing / inventory) + `--apply-sort` dependency-based reordering; `--init <layer-root>` writes both config files for a new project or user | `python …\index_generator.py --config <layer>\工具脚本\索引生成器.config.json [work] [--apply-sort]` |
| `replica_audit.ps1` | Three-way hash audit Win canonical vs WSL vs cluster (drift resolves in favor of Win; remote-only files are pending back-copies; renamed deployments are recognized) | `pwsh -File …\replica_audit.ps1 -Config <layer>\工具脚本\副本巡检.config.json` |
| `structure_audit.py` | Work-level AGENTS.md directory-structure drift reconciliation (unmentioned / vanished; reports, never edits) | `python …\structure_audit.py --config <layer>\工具脚本\索引生成器.config.json` |

All three engines follow the **report/generate, never silently edit** rule; the authoritative rules and an onboarding checklist live in [references/audit-and-tooling.md](references/audit-and-tooling.md).

## Scope boundaries

- **Mesh reliability verification** (convergence studies, GCI, benchmark-track policy): a research method, not a project skeleton — outside this skill;
- **WSL bridging, GitHub connectivity** and similar environment setup: each has its own documentation;
- **Literature libraries and manuscript citations**: the job of the academic-manuscript / academic-markup / note-gen skills;
- **Plot styling and post-processing pitfalls**: the academic-plotting / paraview-pitfalls skills;
- This skill carries no physics code; the companion engines (index / audit / reconcile) are generic tools, all project differences go through config, and machine paths never enter the skill.
