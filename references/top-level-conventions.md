# Top-level directory conventions (common to all works)

> Canon lives with the openfoam-research-init skill; a project's work-level AGENTS §1 is an instance (major revisions sync both ways).
> Generic wording: project synced drive = any file-sync drive (e.g. Nutstore, Dropbox, OneDrive); project repo = the git repository carrying this work.

## Top-level directory set

- `手稿\` (manuscripts), `AI分析\` (frozen AI snapshots), `operations\` (pipeline runtime) stay at the top level, never merged into any of the four lines.
- `手稿\` gets an `AGENTS.md` at scaffold time (pipeline pointer; template ships with the academic-manuscript skill) + `reference\` (RIS/ENW citation pool, held per work) + `figures\` (figures; every figure source must be regenerable); the symbol registry is created with the first manuscript, not pre-built.
- `AI分析\` holds historical-survey / snapshot documents, **for reference only, not maintained** — after a directory rename or move, stale path references inside it are not fixed.
- `operations\` is the **runtime workspace of the AI pipeline** (note/marker pipeline operation queue `pending-ops.json`, completion table `completed-ops.json`, result stream `results.ndjson`, digest `ops_digest.txt`, literature-recall context `recall-context.json`) — **regenerable runtime products: do not hand-edit, do not commit**; deployment scripts/packages do not belong here (they go to `算例集合\` under freeze).
- A work under this convention has **no private tools directory**: generic conversion and generation tools are shared at the layer level (or project tools area); tools surface only as pointer lines in the work-level AGENTS.

## Synced-drive asset library

- Location: a deep path on the synced drive named after the work (`<sync-root>\<project path>\<work>\素材库\`).
- **Stores only material that cannot be regenerated by code** (experiment photos, micrographs, …); regenerable rendered contours go to `数据\衍生\` per-topic buckets — PNG/JPG never enter git, defended by the root `.gitignore`.
- Heavy assets (.ai layout projects, exported figures) live in same-named deep directories on the synced drive (`<work>\研究文档\<topic>\` etc.); the repo keeps only the exported products.

## .ai export rules

- Every .ai under the synced drive's `研究文档\` and `手稿\` **must, once finalized, export one tiff and one png (500 dpi) into the corresponding place in the project repo** (for embedding in manuscripts/documents; kept out of git by `.gitignore`, regenerable from the .ai).
- **Export with useArtboards off**, so the exported bounds match the document.
- If the AI forgets to export, the user does it manually — a backstop, not an exemption from "export at finalization".
