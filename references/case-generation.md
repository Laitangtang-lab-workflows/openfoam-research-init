# Case generation: the explicit-parameter philosophy (meshgen pattern)

> Origin: this file is the canon, distilled from the practice of an actual simulation project's layer-level `公共库\meshgen\` (README and library structure) and each research part's `工况生成\` scripts.

## 1. Two-layer structure: shared library (layer/project-group) + condition drivers (per research part)

Case generation (blockMeshDict / setFieldsDict / snappyHexMeshDict / STL, …) is never written as "one big script managing all conditions". It is two layers; **only the library is shared, condition drivers belong to their research part** (no generic cases layer — every condition has an unambiguous research owner; mixing them breaks the strict "research part ↔ code directory" correspondence); when shared across projects, the library is hoisted to the project-group level (outside each project's `代码\`):

```
<project-group>/公共库/
└── meshgen/                      # shared library (one library per geometry/physics family)
    ├── default_params.py         # parameter dict (required / family defaults, layered) + scale formulas
    ├── generate_case.py          # dictionary generation (required-arg gate + read-back verification)
    ├── generate_stl.py           # STL generation (solid names consistent with the case BC table)
    └── system_files.py           # system companions (coordinate shifts / controlDict / decomposeParDict)
<project>/<research part>/工况生成/
└── <series>/run_<condition>.py   # condition drivers, grouped by purpose (groups follow research parts)
```

- **Shared library**: only generation logic unrelated to specific conditions; **stdlib only, zero third-party dependencies, zero machine paths** (no edits needed when switching machines); each geometry/physics family gets its own library — no forced unification.
- **Parameter layering (against silent inheritance — same value ≠ may be implicit)**: physics judgments (geometry dimensions, resolution, property groups, scale coefficients, …) are **required with no defaults** — one missing and it errors out; family design constants (reference lengths, gradients, unit scales) may default but are printed in the read-back verification table. Empirical coefficients and scale formulas are enforced at the same point (e.g. in `nozzle_h(B, H, dn, k=...)` the empirical coefficient k is required).
- **write-then-verify**: after writing files, the generator **reads them back**, verifies structure and prints a physics-parameter table; material-type fields use an independent read-back verification module (reading from the generated files, decoupled from the writing implementation — cutting the closed loop of "what changed is what gets checked").
- **Condition scripts**: copy one, change parameters, done. Script name = condition name with a `run_` prefix and dots replaced by underscores (`case_H0.75` → `run_case_H0_75.py`); an optional `--out DIR` overrides the default output (default: the matching series directory in the case archive); addressing anchors via `__file__` up to the project root, then `..\公共库` to find the library (deployment to the run side keeps the in-repo relative structure).
- **Deployment coupling stays separate**: parts coupled to the deployment environment (WSL paths, assembly flows, …) live in a separate `<series>_common.py` deployment layer, never inside the shared library.

## 2. All parameters explicit

- Every condition script **lists all of its parameters explicitly at the top** (geometry, resolution, material group, unit scale): one file describes one case — no chasing chains of function defaults;
- Defaults live in exactly one place, `default_params.py`; the explicit overrides inside a condition script are the complete difference set;
- Generated output and the frozen copy can be reconciled **line by line / byte by byte** (regeneration verification): after touching a generator, rerun and diff — it is trusted only if identical. This is the burden of proof that "a script can fully replace a hand-written case".

## 3. Intermediate artifacts: deterministic regeneration, never stored

- `*.stl`, mesh products (polyMesh/eMesh), … are **neither committed nor stored as entities**: they are deterministically regenerated by generator scripts (verified identical against the frozen copy);
- gitignore as a backstop against accidental commits;
- what the case archive freezes is **dictionaries and parameters** (system dictionaries + parameter scripts), not binary intermediates.

## 4. Naming and unit scales

- solid/patch names match the case BC table's logical names (e.g. STL solid names lowercase; final snappy patch name = `geometry_region`) — eliminating any "rename after generation" step;
- the length-unit scale is uniform inside a library (e.g. `convertToMeters 1` = mm), never drifting per case;
- special scalings (e.g. one component's dimension scaling with a condition parameter) are concentrated in the shared library's formulas; condition scripts pass physical parameters only.
